# GitHub Loading Protocol

Trigger PERW for problem discovery, paper ideation, viewpoints, literature/research gaps, policy/institution research, data/measurement feasibility, regional/spatial research, empirical design, causal or non-causal inference, regression/robustness/mechanism, manuscript writing, journal selection, review, or submission.

Prefer live verified repository sources. Fetch CURRENT.md first; new projects use current stable, while ongoing projects preserve their recorded adopted version. Then load core/PRINCIPLES.md, core/ROLE_ROUTING.md, core/WORKFLOW.md and only relevant stage/gate/protocol files. Use the [authority and navigation map](../README.md#authority-and-navigation) to locate the controlling rule rather than reload the whole repository.

If live sources cannot be verified, disclose the access failure. Use a previously verified cache only when its provenance and relevant coverage can be established. State the exact cached PERW version, repository/revision or verification record, cache location and last verification date where known; mark missing provenance details UNKNOWN. Never describe that cached version as the current online release without live evidence. For ongoing projects, preserve the adopted version and any material uncertainty; do not silently migrate or mix incompatible versions. If no suitable verified cache is available, request the needed files or source and leave dependent conclusions pending rather than pretend PERW was loaded.
